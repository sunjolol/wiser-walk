### 4. [medium] site/src/pages/api/auth/email.ts:143
**Problem:** The awaited work inside the hook adds up to 4,500 ms before the response is written: alreadySent (LOG_TIMEOUT_MS 500) + sendTransactional (SEND_TIMEOUT_MS 3500) + record (500). Supabase's whole budget is 5 s including cold start. record() in particular is awaited after the email has already gone, purely to write a log row. The function this route lives in also serves /r/[quiz]/[code] (prerender=false), so the cold start is the full result renderer: the built _render.func is 23 MB on disk (994 KB app JS + 22 MB node_modules).
**Scenario:** Brevo is slow on the free plan (README step B1 notes sending has to be switched on by a human). The send takes 3.4 s, record takes 0.4 s, alreadySent took 0.4 s, and with a 1 s cold start the invocation passes 5 s. Supabase abandons it. A timeout is neither 429 nor 503, so it is not retried: the person receives the email but the sign-up call reports a failure, and because record() never completed there is no log row either, so /account/setup/ tells the owner "Supabase has never asked us to send an email." He then debugs a flow that is working.
**Fix:** Respond as soon as the send resolves and let record() run without await (or give it ~150 ms), and cut alreadySent to ~250 ms. Keeping the send's 3.5 s is right; the 1 s of bookkeeping around it is what pushes it over.
